# 상품·사이즈 매칭과 가격 계산 기준

## 1. 무신사 회원가

### 조회 방법

구매 가능한 옵션(사이즈)마다 아래 순서로 조회한다(`crawler.price_option`).

1. `POST cart.musinsa.com/api2/cart/v1/cart` 에 `isOrder: true`, 수량 1로 해당 옵션을 담는다. 일반 장바구니가 아니라 "바로구매"용 주문 대기 항목이다.
2. `GET order.musinsa.com/api2/order/v1/orders/order-form` 에서 **상품번호와 옵션번호가 모두 일치하는** 항목을 찾는다. 없으면 실패로 처리한다.
3. `GET order.musinsa.com/api2/order/v1/goods-coupons` 로 그 옵션 판매가에 적용 가능한 쿠폰 목록을 받는다.

주문 확정, 결제 요청은 하지 않는다. 사용자 계정의 "바로구매" 대기 항목이 마지막으로 조회한 옵션으로 바뀌는 것이 유일한 계정 변경이다.

### 계산식 (`crawler.compute_final_v2`, 기존 GUI 규칙 그대로)

```
쿠폰 적용가   = 옵션 판매가 − 최대 할인 쿠폰(쿠폰 목록 중 할인액이 가장 큰 것)
등급 할인액   = 내림10(쿠폰 적용가 × 회원 등급 할인율)            ← 주문서가 등급 할인 가능이라고 할 때만
적립금 선할인 = 상품 적립금 + 내림10((쿠폰 적용가 − 등급 할인액) × 등급 적립률)   ← 주문서가 선할인 가능이라고 할 때만
회원가        = 쿠폰 적용가 − 등급 할인액 − 적립금 선할인
```

| 항목 | 회원가에 포함 여부 |
|---|---|
| 최대 할인 쿠폰 1장 | 포함 |
| 회원 등급 할인 | 포함 |
| 적립금 선할인 | 포함 |
| 배송비 | 미포함 |
| 결제수단 프로모션(카드·페이 즉시할인) | 미포함 |
| 구매 후 적립 예정 적립금 | 미포함 |

화면과 엑셀에는 판매가, 쿠폰명, 쿠폰 할인액, 등급 할인액, 적립금 선할인액을 사이즈마다 따로 남긴다.

### 지켜야 하는 규칙과 구현

| 규칙 | 구현 | 테스트 |
|---|---|---|
| 모든 사이즈를 빠짐없이 처리 | 옵션 API의 삭제·리다이렉트 옵션만 제외하고 전부 `musinsa_variants`에 저장. 사라진 옵션은 삭제하지 않고 표시만 내림 | `test_every_size_is_stored_and_each_option_gets_its_own_price` |
| 옵션별 실제 가격 사용 | 옵션마다 자기 주문서를 조회 | 같은 테스트, `test_each_option_uses_own_order_price_and_coupon` |
| 첫 사이즈 가격을 복사하지 않음 | 기본 모드는 옵션마다 조회. 빠른 모드는 옵션 추가금이 같은 사이즈끼리만 대표값을 쓰고 출처 열에 "대표 옵션 N 값"이라고 적는다 | `test_grouped_mode_reuses_only_equal_option_prices_and_says_so` |
| 다른 옵션의 주문서 가격으로 대체하지 않음 | 주문서에서 옵션번호가 다르면 실패 | `test_wrong_size_order_item_is_rejected` |
| 조회 실패를 품절로 처리하지 않음 | 실패는 `priceStatus=error`, 품절은 재고 API가 품절이라고 한 경우만 | `test_failed_lookup_is_an_error_not_sold_out_and_never_a_public_price`, `test_denied_options_are_not_sold_out` |
| 실패 시 공개 가격을 회원가로 쓰지 않음 | 회원가 칸을 비우고 "회원가 확인 실패" | `test_failed_member_price_never_uses_public_price` |
| 재조회 실패 시 | 이전 검증값과 그 조회 시각을 유지하고 "회원가 갱신 실패(이전 값)" + 오류 표시 | `test_refresh_failure_keeps_last_verified_price_as_stale` |

### 기존 GUI와 달라진 점

GUI는 상품당 첫 번째 구매 가능 옵션 하나의 회원가를 구해 모든 사이즈 행에 같은 값으로 표시했다. 웹은 사이즈마다 값을 구한다. GUI와의 호환을 위해 `products` 테이블의 상품 단위 열(`finalPrice` 등)에는 지금도 첫 번째 구매 가능 옵션의 값을 넣는다.

## 2. KREAM 가격 (`shop_comparator/shops/kream_api.py`)

`api.kream.co.kr/api/p/options/display` 를 `picker_type=buy`, `picker_type=sell` 로 한 번씩 호출한다.

| 값 | 정의 | 응답에서 읽는 곳 |
|---|---|---|
| 즉시구매 최저가 | 새 상품을 지금 바로 살 수 있는 가격 중 가장 낮은 값 | `instant_buy` 액션의 `price`, 그리고 버튼 문구에 "즉시 구매"가 있는 `buy` 액션의 `price` |
| 즉시구매 배송 유형 | 최저가가 나온 배송 유형(일반배송·빠른배송·해외배송) | 같은 액션의 `delivery_method` |
| 즉시판매가 | 지금 바로 팔 수 있는 가격 = 가장 높은 구매 입찰가 | sell 쪽 `instant_sell` 버튼 |
| 입찰 전용 | 즉시구매 후보가 없고 구매 입찰만 가능한 사이즈 | `bid_buy` 액션만 있음 |

선택 기준

- 한 사이즈에 배송 유형별로 여러 가격이 있으면 **가장 낮은 값**을 즉시구매 최저가로 쓰고, 어떤 배송 유형인지 함께 저장한다. 후보 전체는 `kream_quotes.candidates`에 남긴다.
- 95점·보관판매 상품(`quality`가 1이 아닌 항목, `buy_95`, `add_to_cart`)은 제외한다.
- 구매 입찰만 가능한 사이즈는 즉시구매가를 비워 두고 상태를 "즉시구매 불가(입찰만)"으로 표시한다. 입찰가를 즉시구매가로 쓰지 않는다.
- 즉시구매가와 즉시판매가(구매 입찰 최고가)는 서로 다른 열에 저장한다.
- KREAM 가격은 화면 표시 판매가다. 검수비, 수수료, 배송비는 포함하지 않는다.

실제 응답 발췌(`tests/fixtures/kream_buy_15251_excerpt.json`)에 대한 결과: 사이즈 220은 일반배송 76,000원과 해외배송 116,000원 중 76,000원을 선택하고, 빠른배송 85,000원(95점)은 제외한다.

## 3. 사이즈 매칭 (`comparison_service.size_key`)

원본 사이즈 문자열은 그대로 저장·표시하고, 매칭에는 정규화 키를 쓴다. **같은 사이즈 체계끼리만** 매칭한다.

| 원본 예 | 정규화 키 | 설명 |
|---|---|---|
| `250`, `250mm`, `W250`, `M250`, `KR 250` | `MM:250` | mm 사이즈. `W`/`M`은 KREAM이 성별 구분으로 붙이는 접두어 |
| `227.5` | `MM:227.5` | |
| `US 8` | `US:8` | |
| `UK 8` | `UK:8` | `US:8`과 다르다 |
| `2XL`, `XXL` | `A:XXL` | 의류 표기 통일 |
| `FREE`, `ONE SIZE`, `OS` | `ONE` | |
| `L(100)`, `8` 등 | `=:원문` | 체계를 알 수 없으면 같은 문자열끼리만 매칭 |

- US↔mm, UK↔mm 같은 환산은 하지 않는다. 체계가 다르면 "KREAM에 없는 사이즈"로 남는다.
- KREAM 쪽에 같은 키가 둘 이상이면(예: `250`과 `W250`이 함께 있음) 어느 것도 고르지 않고 "KREAM 사이즈 중복"으로 표시한다.
- 무신사에 없는 KREAM 사이즈는 "무신사에 없는 사이즈" 행으로 볼 수 있다(상품·비교 탭의 체크박스).

GUI는 `size_converter.normalize_size`로 숫자만 뽑아 비교했기 때문에 `US 8`과 `UK 8`이 같은 사이즈로 매칭될 수 있었다. 웹은 이 방식을 쓰지 않는다.

## 4. 상품 매칭

| 매칭 상태 | 조건 | 가격 수집에 사용 |
|---|---|---|
| 모델번호 일치 | 무신사 품번(또는 상품명 속 모델번호)과 KREAM 모델번호가 같은 후보가 하나뿐 (`match_method=model_code`) | 예 |
| 이미지 검토 | 저장한 썸네일을 나란히 비교한 AI 보조 검토로 등록 (`match_method=image_review`, 사람 미검수) | 예(검수 권장) |
| 검수 승인 | 웹의 VLM 검토 탭에서 사람이 승인 (`match_method=human_review`) | 예 |
| 직접 지정 | 매칭 탭 또는 수집 입력에서 KREAM URL을 지정 (`match_method=manual`, 신뢰도 1.0) | 예 |
| 자동 검증 | `kream_crawler.search_product` 결과가 `product_matcher.select_best_kream_match` 검증을 통과 (`match_verified=1`) | 예 |
| 미검증 | GUI 시절 CSV·캐시에서 온 ID로 검증 기록이 없음 | 아니오(매칭 탭에서 [선택 승인]하거나 다시 검색) |
| 매칭 없음 | | 아니오 |

- 모델번호 대조, 이미지 판정(VLM), 기존 규칙과의 성능 비교는 [matching-evaluation.md](matching-evaluation.md)에 있다.
- 화면, 엑셀, CSV에 매칭 상태, 신뢰도, 방식, 근거를 함께 표시한다.
- 같은 KREAM 상품이 이미 다른 무신사 상품에 검증 매칭되어 있으면 새로 연결하지 않는다.
- KREAM 검색과 시세 조회는 로그인 없이 실행된다.
- 검증을 통과한 결과가 없으면 `kream_search_blacklist.csv`(검색 제외 목록, GUI와 공유)에 추가해 반복 검색을 막는다. 매칭 탭에서 해제할 수 있다.
- 환경변수 `KREAM_TRUST_EXISTING_MATCHES=1`이면 GUI처럼 미검증 매칭도 사용한다.

## 5. 비교 행의 상태값

| 상태 | 뜻 |
|---|---|
| 비교 완료 | 회원가와 즉시구매가가 모두 있음 |
| 품절 | 무신사 재고 API가 품절이라고 응답 |
| 회원가 미조회 | 재고만 수집했음 |
| 회원가 확인 실패 | 조회했으나 실패, 이전 값 없음 |
| 회원가 갱신 실패(이전 값) | 재조회 실패, 이전 검증값을 조회 시각과 함께 표시 |
| 상품 매칭 필요 / 매칭 검증 필요 | 매칭이 없거나 미검증 |
| KREAM 미수집 / KREAM 조회 실패 | 시세를 아직 받지 않았거나 마지막 조회가 실패 |
| KREAM에 없는 사이즈 / KREAM 사이즈 중복 | 같은 체계의 사이즈가 없거나 둘 이상 |
| 즉시구매 불가(입찰만) | 구매 입찰만 가능 |
| 무신사에 없는 사이즈 | KREAM에만 있는 사이즈 |

가격 차이 = KREAM 즉시구매 최저가 − 무신사 회원가. 판매 차익 = KREAM 즉시판매가 − 무신사 회원가. GUI 형식 CSV만 기존대로 무신사 − KREAM 부호를 쓴다.

## 6. 결과에 남기는 정보

사이즈 행마다 무신사 조회 시각, 회원가 출처(해당 옵션 주문서 / 대표 옵션 값), 무신사 오류, KREAM 조회 시각, KREAM 오류, 매칭 상태·신뢰도·방식을 남긴다. 비교 엑셀의 "기준" 시트에는 가격 포함 범위와 선택 기준을 적는다.
