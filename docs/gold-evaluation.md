# 사람이 만드는 평가 정답 (정답 검수 모드)

기존 평가의 정답은 모델번호 규칙과 AI 보조 검토에서 왔다. 독립적인 정답이 아니다. 이 문서는 사람이 AI의 답을 보지 않고 정답을 만드는 방법과, 그 정답으로 평가를 실행하는 방법을 적는다.

**현재 상태: 사람이 만든 정답 0건.** 화면과 평가 코드만 준비돼 있다. AI나 스크립트가 정답을 대신 채우지 않는다.

## 1. 검수하는 방법

1. 서버를 켠다: `powershell -ExecutionPolicy Bypass -File restart_server.ps1`
2. 브라우저에서 `http://127.0.0.1:8765/#gold` 를 연다. (상단 탭의 **정답 검수**)
3. **검수자 (별칭)** 칸에 별칭을 적는다. 본명이나 연락처는 쓰지 않는다.
4. 사례가 한 건씩 나온다. 왼쪽이 무신사 원본, 오른쪽이 KREAM 후보다. 필요하면 "무신사 페이지", "KREAM 페이지" 링크로 실제 상품을 연다.
5. 셋 중 하나를 누른다.
   - 같은 상품(같은 모델, 같은 색상)인 후보의 **[후보 N 선택]** 을 누르고 **[선택한 후보가 같은 상품 · 저장]**
   - 후보 중에 같은 상품이 없으면 근거를 적고 **[동일 상품 없음 · 저장]**
   - 이미지와 정보로 가릴 수 없으면 근거를 적고 **[판단 불가 · 저장]**
6. 저장하면 다음 미완료 사례로 넘어간다. 60건을 마치면 "모든 사례에 정답을 저장했습니다"가 나온다.
7. 고치려면 [← 이전]으로 돌아가 다시 저장한다. 이전 라벨은 지워지지 않고 최신 라벨이 쓰인다.

한 번에 다 할 필요는 없다. 진행은 저장되고, [미완료 사례로]를 누르면 이어서 할 수 있다.

## 2. 화면에 보이는 것과 숨기는 것

| 보이는 것 | 숨기는 것 |
|---|---|
| 원본과 후보의 이미지, 상품명, 브랜드, 모델번호, 옵션(사이즈) | VLM 판정, 모델 출력 신뢰도, 추천 후보 |
| 무신사·KREAM 페이지 링크 | 기존 규칙의 결론, 현재 등록된 매칭과 그 상태 |
| 사례 번호와 진행 상황 | 사례를 고른 묶음(선정 기준), 검색 순서, 작업 요약 띠 |

- 후보는 고정된 임의 순서로 나온다. 검색 결과 순서가 아니다.
- KREAM 후보의 옵션은 예전에 가격을 수집한 후보에만 있다. 일부 후보에만 보이면 그 후보가 매칭돼 있었다는 뜻이 되므로, 한 사례의 모든 후보에 옵션이 있을 때만 보여 준다.
- 화면 API(`/api/gold`)의 응답에는 방법의 답이 들어 있지 않다(`tests/test_gold.py`가 확인).
- 정답을 저장한 뒤에도 이 화면에서는 AI의 답을 보여 주지 않는다. 비교는 평가 명령으로 한다.

## 3. 평가 사례 60건

2026-10-09에 실제로 수집한 무신사 신발 랭킹 상품에서 골라 그 시점의 입력을 고정했다(`python -m shop_comparator.matching.gold build`, 시드 고정).

| 묶음 | 수 | 고른 기준 |
|---|---|---|
| 모델번호 일치 후보 | 15 | 모델번호가 일치하는 후보가 하나 |
| 색상·모델 충돌 | 15 | 같은 모델번호를 쓰는 후보가 여러 개, 규칙과 VLM이 다른 후보를 고름, 같은 계열의 다른 모델번호 후보가 있음 |
| 닮은 다른 상품 | 15 | 규칙(`local`)이 등록한 매칭, 모델이 등록한 매칭, VLM이 "동일"이라고 한 상품 |
| 동일 상품 없음 의심 | 15 | VLM이 "다름" 또는 "불확실"이라고 한 상품 |

**이 묶음은 표본을 고르게 하려는 기준일 뿐 정답이 아니다.** 기존 규칙의 `local` 판정과 모델번호 일치도 검수 대상에 들어 있다.

표본의 편향: 무작위 표본이 아니다. 기존 규칙과 VLM의 결론을 보고 골랐고, 어려운 사례의 비중이 실제 수집분보다 높다. 이 60건에서 나온 비율을 전체 수집분의 정확도로 읽으면 안 된다.

## 4. 저장되는 것

운영 DB와 분리된 `evaluation_data/gold/`에 저장한다(git에 올리지 않음).

| 파일 | 내용 |
|---|---|
| `cases.json` | 사례별 고정 입력: 사례 ID, 무신사 상품(상품명, 브랜드, 모델번호, 옵션), 후보(같은 항목), 이미지 파일과 SHA-256, 수집 시각, 고정 시각, 입력 해시 |
| `images/<사례>/` | 고정 시점의 썸네일 사본. 원본 이미지가 바뀌어도 같은 입력으로 다시 볼 수 있다 |
| `method_outputs.json` | 각 방법이 같은 입력에 낸 답과 검색 순서. 화면으로 보내지 않는다 |
| `labels.sqlite` | 라벨과 검토 시간 기록 |

라벨 한 건: 사례 ID, 검수자 별칭, **origin**, 결정(후보 / 없음 / 판단 불가), 고른 후보, 판단 근거, 입력 해시, 시작·종료 시각, 소요 시간, 탭 이탈 시간과 횟수, 저장 시각.

**origin**으로 누가 만들었는지 구분한다.

| origin | 뜻 | 정답으로 사용 |
|---|---|---|
| `human_ui` | 사람이 운영 서버의 정답 검수 화면에서 저장 | 예 |
| `automation` | 스크립트가 화면을 조작(데모·캡처·테스트는 `SHOP_AUTOMATION=1`) | 아니오 |

개인정보와 로그인 정보는 들어가지 않는다. 사례 정의(`cases.json`, `method_outputs.json`)는 `python -m shop_comparator.matching.gold publish`로 `docs/evaluation/gold/`에 복사해 저장소에 넣었다. 라벨을 저장소에 넣을지는 검수를 마친 뒤 정한다(`gold export`가 CSV를 만든다).

## 5. 검수를 마친 뒤 실행할 평가

```powershell
.\.venv\Scripts\python.exe -m shop_comparator.matching.gold status           # 사람 정답 건수 확인
.\.venv\Scripts\python.exe -m shop_comparator.matching.gold_eval             # 보고서
.\.venv\Scripts\python.exe -m shop_comparator.matching.gold_eval --json --save   # 분자·분모·계산식 포함, report.json 저장
.\.venv\Scripts\python.exe -m shop_comparator.matching.gold export           # 라벨과 검토 시간 CSV
```

비교하는 방법

| 기호 | 방법 | 비고 |
|---|---|---|
| A0 | 기존 매칭 방식 (품번 일치, 없으면 첫 결과) | 저장된 검색 순서로 재현 |
| A | 모델번호·규칙 기반 매칭 | |
| B | 텍스트 점수 규칙 (상품명·브랜드·모델번호) | 고정 규칙으로 점수를 매긴다. **언어 모델이 아니다** |
| C | 저장된 VLM 판정 (`gpt-5.4-mini`) | 저장된 판정이 없는 7건은 미실행 |
| D | 규칙 + VLM | |
| B-LLM | 텍스트 전용 LLM | **미실행.** 유료 호출이 필요하고 예산이 승인되지 않았다 |

지표와 계산식 (`--json` 출력에 분자·분모가 함께 나온다)

| 지표 | 계산 |
|---|---|
| 동일 상품 선택의 정밀도 | 맞게 고른 수 ÷ 후보를 고른 수 (실행된 사례) |
| 잘못 선택한 상품 수 | 후보를 골랐는데 사람의 정답과 다른 수 (동일 상품 없음 사례에서 고른 것 포함) |
| 정답 후보를 찾은 비율 | 맞게 고른 수 ÷ 사람이 후보를 고른 사례 중 실행된 수 |
| 보류·판단 불가 비율 | 판단하지 않고 사람에게 넘긴 수 ÷ 실행된 사례 |
| 동일 상품 없음 사례에서 잘못 선택한 수 | 후보를 고른 수 ÷ 사람이 "동일 상품 없음"으로 답한 사례 중 실행된 수 |
| 실행·미실행 | 저장된 결과로 답할 수 있는 사례 수와 그렇지 않은 수 |

- 미실행은 틀림이나 보류에 넣지 않고 따로 센다.
- 방법마다 실행 범위가 달라 "방법별 전체" 표는 서로 직접 비교하면 안 된다. 다섯 방법이 모두 실행된 사례만으로 다시 계산한 **공통 실행 집합** 표를 비교에 쓴다.
- 사람이 "판단 불가"로 답한 사례는 채점에서 빼고 건수만 적는다.
- 사람 정답이 0건이면 보고서는 "사람 검수 대기"만 표시하고 성능 수치를 내지 않는다.

## 6. 한계

- 검수자가 한 명이면 검수자 간 일치도를 알 수 없다. 두 번째 검수자가 같은 화면에서 다른 별칭으로 검수하면 `--reviewer`로 나눠 볼 수 있다.
- 모델번호가 화면에 보이므로 사람도 모델번호가 같은 후보로 기울 수 있다.
- 60건, 신발 한 범주, 한 시점이다.
- C의 저장 판정은 이미지와 함께 상품명·모델번호도 받은 결과다.
