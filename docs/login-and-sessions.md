# 로그인과 세션 관리

## 1. 원칙

- 무신사, KREAM, POIZON은 입력란, 로그인 버튼, 상태 표시, 실패 처리를 각각 따로 가진다. 한 쇼핑몰의 로그인 실패나 만료가 다른 쇼핑몰 상태를 바꾸지 않는다.
- "로그인됨"은 회원 전용 요청이 실제로 성공했을 때만 표시한다. 주소가 바뀌었다거나 쿠키가 있다는 것만으로는 성공으로 보지 않는다.
- 비밀번호는 저장하지 않는다.

## 2. 로그인 흐름 (`shop_comparator/shops/site_login.py`)

```
웹 로그인 탭에서 아이디·비밀번호 입력 → POST /api/login/<site>  (본문은 메모리에서만 사용)
  → 쇼핑몰 전용 Chrome 프로필로 "보이는" Chrome 창을 연다
  → 로그인 화면에 계정을 입력하고 제출
  → 결과 대기(최대 5분)
       성공 신호: 무신사 app_atk 발급 / KREAM 로그인 화면 이탈 + 토큰 존재
       실패 신호: 쇼핑몰의 오류 문구·경고창 → 즉시 실패로 끝냄(재시도 없음)
       15초가 지나도 둘 다 아니면 "추가 인증 대기"로 표시하고 창을 열어 둔다
  → 인증 확인 요청(아래 3절) 성공 → "로그인됨" + 마지막 인증 확인 시각 저장
```

| 쇼핑몰 | 로그인 화면 | 입력 | 기존 함수와의 관계 |
|---|---|---|---|
| 무신사 | `https://www.musinsa.com/auth/login` (→ `member.one.musinsa.com/login`) | `input[title='통합계정 또는 이메일']`, `input[title='비밀번호 입력']`, Enter | `crawler.get_cookie_with_selenium`의 선택자와 `_collect_auth_payload`, `_wait_login_outcome`의 판별 방식을 재사용. 전용 프로필·인증 확인·추가 인증 대기를 더했다. |
| KREAM | `https://kream.co.kr/login/email` | `input[type=email]`, `input[type=password]`, Enter | `kream_login.login_and_save_kream_cookies`는 `/login`에서 입력란을 찾는데, 지금 `/login`에는 네이버·Apple·휴대폰 버튼만 있다. 주소를 바꾸고 `_extract_token_and_device_id_from_localstorage`만 재사용했다. 기존 함수의 자동화 탐지 우회 옵션은 쓰지 않는다. |
| POIZON | 셀러 센터 | `PoizonSellerCrawler.login` | GUI와 같은 함수 호출 |

### .env 계정

프로젝트 `.env`에 `MUSINSA_ID`/`MUSINSA_PASSWORD`, `KREAM_ID`/`KREAM_PASSWORD`(선택: `POIZON_ID`/`POIZON_PASSWORD`)가 있으면 로그인 카드에 [.env 계정으로 로그인] 버튼이 나타난다. 값은 버튼을 누른 순간 서버가 읽어 로그인에만 쓰고, 어떤 API 응답에도 넣지 않는다(상태 API는 있음/없음만 알려 준다). `.env`는 `.gitignore` 대상이다.

### 수동 로그인(보조 수단)

[창에서 직접 로그인]을 누르면 같은 프로필의 Chrome 창만 열고 사용자가 직접 로그인한다. 네이버·Apple 계정으로 KREAM을 쓰는 경우에 필요하다. 이후 인증 확인은 자동 로그인과 같다.

### 추가 인증·CAPTCHA

프로그램은 CAPTCHA나 본인확인을 대신 풀지 않는다. 화면과 로그에 "열린 Chrome 창에서 추가 인증을 완료해 주세요"를 표시하고 기다리며, 사용자가 완료하면 같은 작업이 이어서 인증 확인까지 진행한다. 5분 안에 끝나지 않으면 실패로 끝나고 다시 로그인 버튼을 누르면 된다.

## 3. 인증 확인

| 쇼핑몰 | 요청 | 판단 |
|---|---|---|
| 무신사 | `GET order.musinsa.com/api2/order/v1/orders/order-form` | 401·403이면 미인증. 5xx는 "만료"가 아니라 오류로 처리. 그 밖의 응답은 회원 세션이 받아들여진 것 |
| KREAM | `GET api.kream.co.kr/api/p/products/74130/sales` (체결 내역) | 회원 토큰이 없으면 요청 없이 미인증. 401·403이면 미인증. 200이고 `items`가 있어야 인증. 시세·검색 API는 로그인 없이도 200이라 확인에 쓰지 않는다 |

같은 확인을 세 군데에서 한다.

1. 로그인 직후
2. 로그인 탭의 [세션 확인] 버튼
3. 무신사 회원가 수집과 KREAM 거래량 필터를 시작할 때마다 (KREAM 매칭·가격 수집은 공개 API라 로그인을 요구하지 않는다)

실사이트 관측(2026-10-09): 로그인하지 않은 프로필에서 무신사 주문서 API는 HTTP 401을 반환했고, 수집 작업은 "무신사 로그인이 필요합니다"로 요청 전에 끝났다. 사용자가 창에서 직접 로그인한 뒤에는 무신사 주문서 API 200, KREAM 체결 내역 API 200이었다.

## 4. 상태 표시

| 상태 | 뜻 | 안내 |
|---|---|---|
| 로그인됨 | 마지막 인증 확인 성공 | 계정(마스킹)과 확인 시각 표시 |
| 로그인 필요 | 이 PC에서 인증 확인에 성공한 적이 없음 | |
| 만료됨 · 다시 로그인 필요 | 이전에는 성공했으나 지금 인증 거절 | "세션이 만료되었습니다. 다시 로그인해 주세요." |
| 추가 인증 대기 | 쇼핑몰이 추가 인증을 요구 중 | "열린 Chrome 창에서 추가 인증을 완료해 주세요." |
| 로그인 실패 | 계정 오류 등으로 쇼핑몰이 거절 | 쇼핑몰이 보여 준 사유 표시 |
| 확인 안 됨 | 아직 확인하지 않음 | |

## 5. 만료 처리와 재로그인

- 작업 도중 인증 오류(401)가 나면 그 작업은 즉시 멈추고 해당 쇼핑몰 상태를 "만료됨"으로 바꾼다. 그때까지 저장한 결과는 남는다.
- 로그인할 때 "서버 실행 중 재로그인용으로 메모리에만 보관"을 체크했다면, 다음 작업 시작 시 만료를 발견했을 때 한 번 자동으로 다시 로그인한다(GUI의 `_execute_kream_api`, `_auto_login_kream`에 해당). 체크하지 않았으면 안내만 한다.
- 보관한 계정은 서버 프로세스 메모리에만 있고 [보관 계정 삭제] 버튼이나 서버 종료로 사라진다.

## 6. 계정정보·쿠키·토큰 취급

| 대상 | 저장 위치 | 노출 방지 |
|---|---|---|
| 비밀번호 | 저장하지 않음(선택 시 프로세스 메모리) | 입력 즉시 로그 마스킹 대상으로 등록. 작업 오류 문구도 마스킹 후 저장. 입력란은 제출 직후 비움 |
| 아이디·이메일 | `site_sessions.account`에 마스킹된 형태(`ab***@domain`)만 | 로그에서도 이메일은 자동 마스킹 |
| 쿠키·세션 | `browser_profiles/<shop>/` (Chrome 프로필, git 제외)와 기존 GUI 저장소(`cookies` 테이블, `cookies.json`, `cookies_token.json`). 무신사 인증 쿠키는 세션 쿠키라 브라우저를 닫으면 프로필에서 사라지므로, `cookies` 테이블의 값을 작업마다 다시 넣는다 | 웹 응답에 포함하지 않음. 모두 `.gitignore` 대상 |
| 디스코드 웹훅 URL | `web_settings` | 응답·화면에는 끝 6자만. 로그에서는 URL 전체 마스킹 |

회귀 테스트 `test_password_never_appears_in_state_logs_or_database`가 상태 API, 로그 API, 작업 이력, DB 파일 바이트에 비밀번호가 없는지 확인한다.

## 7. 브라우저 프로필과 동시 사용

한 프로필은 한 번에 Chrome 하나만 쓸 수 있다. `browser_transport.profile_lock`이 쇼핑몰별로 직렬화한다. 그래서 무신사 로그인 중에는 무신사 수집을 시작할 수 없지만 KREAM 작업은 시작할 수 있다. 모니터링 주기는 잠금을 최대 120초 기다리고, 그래도 못 얻으면 그 주기를 건너뛰고 로그를 남긴다.
