# 검수 정책의 로컬 통합 확인과 매칭 수의 집계 기준

## 1. 로컬 통합 확인

```powershell
.\.venv\Scripts\python.exe scripts\verify_review_policy.py --save
```

| 항목 | 내용 |
|---|---|
| 실제로 쓴 것 | 로컬 Flask 서버(127.0.0.1:8798), CSRF 토큰이 붙은 HTTP 요청, 작업 관리자, 디스크의 SQLite 파일 |
| 데이터베이스 | 운영 DB를 SQLite backup으로 복사한 사본(`integration_check/`). 쿠키·세션·웹훅 설정은 사본에서 삭제 |
| **저장 결과 재생** | 쇼핑몰과 모델을 호출하지 않았다. KREAM 검색은 같은 상품에 대해 예전에 저장된 선택(상품 ID, 방식, 모델 출력값, 근거)을 돌려주고, 가격 요청은 저장된 시세를 돌려준다 |
| **자동화 조작** | 승인·거절·직접 지정은 스크립트가 HTTP로 보냈다. 사람 검수가 아니며 사람 검수로 세지 않는다 |
| 운영 DB | 실행 전후 SHA-256이 같다(변경 없음) |

2026-10-10 실행 결과: **21개 항목 통과, 실패 0, 미실행 0.** 결과 파일은 `docs/evaluation/integration/policy_check.json`.

| 확인한 흐름 | 관측 | 구분 |
|---|---|---|
| AI 제안 생성 | 매칭 작업이 모델의 선택 2건을 등록하지 않고 제안으로 저장 (`suggested 2`, 출처 `matcher:openai`) | 저장 결과 재생 |
| 승인 전 가격 비교 제외 | 매칭 없음, KREAM 가격이 붙은 사이즈 0개. 가격 수집 작업도 시세를 요청하지 않음 | 저장 결과 재생 |
| 반복 실행 | 검색(모델 호출 경로) 재호출 0회, 제안 1건 그대로. 가격 수집의 누락 매칭 검색 경로도 재호출 0회 | 저장 결과 재생 |
| 승인 → 반영 | "검수 승인", KREAM 가격이 비교에 나타남 | 재생 + 자동화 조작 |
| 거절 → 제외 | 가격 비교 제외, 검수 화면 상태 `rejected` | 재생 + 자동화 조작 |
| 기존 AI 등록 | "AI 등록(미검수)", 행은 그대로, 가격 비교 제외, 가격 수집 작업이 시세를 요청하지 않음 | 저장 결과 재생 |
| 기존 AI 등록 승인 | 반영, 원래 출처 `openai`가 `origin_method`에 남음 | 재생 + 자동화 조작 |
| 기존 AI 등록 거절 | "검수 거절", 제외, 행과 출처 보존 | 재생 + 자동화 조작 |
| 규칙 매칭의 출처 | 모델번호 일치는 `model_code` 그대로. 저장된 `local` 판정을 재생하면 바로 등록되고 "규칙 확정" | 저장 결과 재생 |
| 직접 지정의 출처 | `manual`, "직접 지정". 사람 승인은 `human_review`로 따로 표시 | 자동화 조작 |
| GUI에서 들어온 AI 매칭 | 데스크톱 GUI와 같은 함수(`cache_kream_search`, `update_product_kream_id`)로 넣은 `openai` 매칭이 웹에서는 "AI 등록(미검수)"이고 가격 비교에서 제외 | 저장 결과 재생 |
| 사람 검수 기록 | 0건 (이 실행의 승인·거절 4건은 origin `automation`) | 실제 파일 |

이 확인이 말해 주지 않는 것: 실제 쇼핑몰 검색과 실제 모델 호출에서의 동작, 사람이 화면을 조작했을 때의 동작, 여러 작업이 동시에 돌 때의 동작.

## 2. 매칭 수가 왜 다른가: 183 → 155, 그리고 46건

```powershell
.\.venv\Scripts\python.exe scripts\match_counts.py --save      # 운영 DB를 읽기 전용으로 연다
```

2026-10-10 운영 DB 기준(`docs/evaluation/integration/match_counts.json`). 범위가 넷이고 범위마다 숫자가 다르다.

| 범위 | 수 | 뜻 |
|---|---|---|
| `kream_search_cache` 전체 행 | 16,339 | 무신사 상품 → KREAM 상품 ID의 모든 기록. 대부분 예전 GUI가 남긴 근거 없는 ID이고, 지금 상품 목록에 없는 무신사 상품의 행이 많다 |
| 상품 목록(`products`) | 371 | 웹에 보이는 무신사 상품. 숨긴 상품이 없어 활성 상품도 371 |
| 그중 매칭 행이 있는 상품 | 261 | 아래 표의 "상품 목록" 열 합계 |

검수 상태별 (매칭 방식)

| 상태 | 전체 행 | 상품 목록(=활성) | 가격 비교에 사용 |
|---|---|---|---|
| 규칙 확정: 모델번호 일치 (`model_code`) | 153 | 153 | 예 |
| 규칙 확정: 규칙 점수 (`local`) | 2 | 1 | 예 |
| 사람: 직접 지정 (`manual`) | 1 | 1 | 예 |
| **AI 등록(미검수)**: 언어 모델 (`openai`) | **44** | **26** | 아니오 |
| **AI 등록(미검수)**: AI 보조 이미지 검토 (`image_review`) | **2** | **2** | 아니오 |
| 미검증 (근거 없는 예전 ID) | 16,130 | 78 | 아니오 |
| 사람 검수 승인·거절 | 0 | 0 | |

세 숫자의 관계

- **46건** = AI 등록 전체 행(44 + 2). 그중 **28건**이 지금 상품 목록에 있는 상품이고, 나머지 18건은 상품 목록에 없는 무신사 상품의 행이다.
- **183** = 정책 변경 전 화면의 "KREAM 매칭" 수. 활성 상품 중 `match_verified=1`인 상품: 153 + 1 + 1 + 26 + 2.
- **155** = 지금 화면의 수. 활성 상품 중 규칙 확정 또는 사람이 지정·승인한 상품: 153 + 1 + 1.
- 183 − 155 = **28** = 상품 목록에 있는 AI 등록(미검수) 상품 수.

가격 비교 대상 수(활성 상품 + 사용할 수 있는 매칭 + KREAM 시세 수집됨 + 무신사 회원가 있음)는 **179 → 154**다. 183과 179가 다른 것은 매칭은 됐지만 시세가 수집되지 않은 상품이 있기 때문이다.

사람이 검수한 매칭은 0건이다. 미검수 28건을 승인하면 그만큼 다시 포함된다.
