# 검수 업무량과 검토 시간 측정

VLM을 쓰는 목적은 사람이 이미지를 보고 하던 동일 상품 검토를 줄이거나 빠르게 하는 것이다. 이 문서는 그 효과를 **어떻게 재는지**와 **지금 무엇이 측정돼 있고 무엇이 아닌지**를 적는다.

## 1. 현재 상태

| 항목 | 상태 |
|---|---|
| 건수 집계(대상, VLM 판정, 검수 대기, 승인·거절·보류) | 구현됨. VLM 검토 탭 상단과 `/api/review`의 `metrics` |
| 검토 시간 기록 | 구현됨. 카드를 펼친 시각, 결정한 시각, 소요 시간, 탭 이탈 시간과 횟수를 저장. 운영 DB가 아니라 `evaluation_data/gold/labels.sqlite`의 `review_timing`에 둔다 |
| AI 보조 / 수동 구분 | 구현됨. "AI 제안 숨기기"를 켜면 판정·사유·충돌 표시를 가리고 `mode=manual`로 기록 |
| 기록 내보내기 | 구현됨. `검토 시간 CSV` (`/api/export/review-timing.csv`), `검수 기록 CSV` (`/api/export/review-log.csv`) |
| 정답 작성 시간과 운영 검토 시간의 구분 | 구현됨. `context`가 `gold` / `ops` |
| 사람 기록과 스크립트 기록의 구분 | 구현됨. `origin`이 `human_ui` / `automation` |
| **실제 사람의 검토 시간 측정값** | **없음.** 아직 아무도 측정하지 않았다 |
| 수동 대비 AI 보조의 시간 감소율 | **없음.** 측정 전이므로 수치를 제시하지 않는다 |

자동 테스트가 화면을 조작한 시간, 저장된 판정을 재생한 시간, VLM 응답 시간은 사람의 업무 시간이 아니므로 검토 시간에 넣지 않는다. 검토 시간은 사람이 화면에서 내린 결정에서만 나온다.

## 2. 지금 집계되는 값

`vlm_review.metrics(goods_nos)`가 계산한다.

| 값 | 뜻 | 계산 |
|---|---|---|
| 대상 상품 | 선택한 묶음의 상품 수 | 방금 수집한 상품 또는 선택한 상품 |
| 규칙으로 확정 | 사람 검토가 필요 없는 상품 | 등록된 매칭 방식이 `model_code` |
| VLM 검토 대상 | 규칙으로 확정되지 않은 상품 | 대상 − 규칙으로 확정 |
| VLM 판정 | 유효한 제안이 있는 상품 | 형식·후보 검증을 통과하고 후보 목록이 그대로인 최신 판정 |
| 판정 실패·무효 | 제안으로 쓰지 못한 시도 | 이미지 없음, 후보 밖 ID, 형식 오류, API 실패, 오래된 판정 |
| 사람 검수 대기 | 제안은 있고 결정은 없는 상품 | 상태 `pending` |
| 승인 / 거절 / 보류 | 상품별 마지막 결정 | `match_reviews`의 상품별 최신 행 |
| VLM 제안대로 승인 | VLM이 고른 후보를 그대로 승인한 수 | 승인 중 `suggestionDecision = same`이고 후보가 같은 것 |
| 검토 시간 중앙값 | 방식별 중앙값과 건수 | `reviewSeconds`가 있는 결정만 |
| VLM 응답 시간, 토큰 | 호출 기록 | `vlm_suggestions.seconds`, `inputTokens`, `outputTokens` |

"VLM 보조로 확정된 건수"는 "VLM 제안대로 승인"으로 센다. VLM이 고르지 않은 후보를 사람이 승인한 것은 VLM의 성과로 세지 않는다.

## 3. 수동 검토 대 AI 보조 검토를 재는 소규모 측정 절차

같은 사람이 답을 아는 사례를 두 번 보면 두 번째가 빨라진다. 그래서 **두 조건에 서로 다른 상품**을 쓰고, 난이도와 순서를 맞춘다.

### 준비

```powershell
.\.venv\Scripts\python.exe scripts\measurement_plan.py --per-block 12 --session 1
```

이 명령은 운영 DB를 읽기 전용으로 열어 검수 대상 상품을 두 블록에 나누고, 블록별 상품번호 목록과 `evaluation_data/measurement_plan_session1.csv`를 만든다.

| 설계 | 방법 |
|---|---|
| 답을 아는 사례 배제 | 정답 검수 사례 60건, 이전 세션에 쓴 상품, 이미 검수한 상품은 뽑지 않는다 |
| 난이도 맞추기 | (무신사 쪽 모델번호 유무) × (후보 수 1 / 2~4 / 5 이상)로 묶고, 묶음 안에서 두 블록에 번갈아 배정한다 |
| 순서 효과 줄이기 | 홀수 세션은 수동 블록 먼저, 짝수 세션은 AI 보조 블록 먼저. 블록 안 순서는 고정 시드로 섞는다 |
| 조건 통제 | 한 번에 카드 하나만 펼친다. 세션 사이에 쉬는 시간을 둔다 |

### 진행 (세션 1)

1. `http://127.0.0.1:8765/#review` 를 연다. **[저장된 상품 전체에서]** 를 켜고 **[저장된 판정 불러오기]** 를 누른다(네트워크 호출 없음).
2. **블록 A (수동)**: "AI 제안 숨기기"를 **켠다**. 명령이 출력한 블록 A의 상품번호 목록을 검색창에 붙여넣는다. 표시 조건은 "전체"로 둔다.
3. 위에서부터 카드를 하나씩 펼쳐 이미지와 모델번호만 보고 승인·거절·보류한다. 카드를 펼친 순간부터 버튼을 누를 때까지가 기록된다.
4. 5분 이상 쉰다.
5. **블록 B (AI 보조)**: "AI 제안 숨기기"를 **끈다**. 블록 B의 목록을 붙여넣고 같은 방식으로 검토한다.
6. 정답 검수 탭의 **[검토 시간 CSV]** 를 받는다.

세션 2는 `--session 2`로 새 상품을 뽑아 순서를 바꿔(AI 보조 먼저) 다른 날에 한다. 두 세션을 합치면 순서의 영향이 상쇄된다.

### 기록되는 값 (`review_timing`, CSV 열)

| 열 | 뜻 |
|---|---|
| `context` | `ops`(운영 검토) 또는 `gold`(정답 작성). 둘을 섞지 않는다 |
| `caseId` | 운영 검토는 무신사 상품번호, 정답 작성은 사례 ID |
| `mode` | `manual`(AI 제안 숨김), `assisted`(AI 보조), `blind`(정답 작성) |
| `origin` | `human_ui`(사람) 또는 `automation`(스크립트). **집계에는 `human_ui`만 쓴다** |
| `startedAt`, `endedAt` | 카드를 펼친 시각과 결정한 시각 (UTC) |
| `seconds` | 소요 시간 |
| `hiddenSeconds`, `interruptions` | 다른 탭·창으로 나가 있던 시간과 횟수. 중단된 건을 가려낼 때 쓴다 |
| `decision`, `kreamId` | 최종 결정 |

### 집계

1. `origin = human_ui`, `context = ops`인 행만 남긴다.
2. `hiddenSeconds`가 큰 행(예: 10초 이상)은 중단된 건으로 표시하고, 포함한 결과와 제외한 결과를 둘 다 적는다. 순수 검토 시간은 `seconds − hiddenSeconds`다.
3. `mode`별 건수, 중앙값, 사분위수를 구한다.
4. 두 블록의 결정이 다른 근거(모델번호, 이후의 정답)와 어긋나는 건수를 함께 적는다. 빨라졌어도 틀리면 의미가 없다.
5. 보고에는 검수자 수, 세션 수, 조건별 건수, 중앙값과 범위, 제외한 건수와 이유를 적는다.

### 이 절차의 한계

- 검수자가 한 명이면 개인차를 알 수 없다.
- 블록당 12건은 작다. 방향을 보는 용도이고, 차이를 주장하려면 세션을 늘려야 한다.
- 난이도 묶음은 겉으로 보이는 특징으로 나눈 것이라 실제 난이도와 다를 수 있다.
- AI 제안을 본 사람은 제안을 따르는 쪽으로 기울 수 있다(자동화 편향). 4번의 정확도 비교가 필요한 이유다.
- 정답 작성 시간(`gold`)은 AI를 숨긴 조건의 시간이지만 화면과 과제가 달라 운영 검토 시간과 직접 비교하지 않는다.

## 4. 실제 측정이 필요한 항목

| 항목 | 필요한 것 |
|---|---|
| 수동 검토 시간과 AI 보조 검토 시간 | 사람이 3장의 절차로 직접 검토 |
| VLM 제안의 실제 정확도 | 사람이 승인·거절한 결과 (지금의 라벨은 AI 보조 검토이며 사람 미검수) |
| 하루 처리량, 실제 운영에서의 검수 비율 | 실제 수집 묶음 여러 개에서의 기록 누적 |

## 5. 저장된 데이터로 지금 말할 수 있는 것

2026-10-09 수집분 246개 기준(저장된 판정, 사람 검수 전).

- 규칙으로 확정된 상품 153개는 이미지 검토가 필요 없다.
- 나머지 93개 중 VLM이 후보를 제안한 것은 23개, "다름"이 66개, "불확실"이 4개다.
- 따라서 사람이 **먼저 봐야 할 후보는 23개**로 좁혀진다. 다만 "다름" 66개 안에 놓친 동일 상품이 있는지는 확인하지 않았으므로, "검토 대상이 93개에서 23개로 줄었다"고 단정할 수 없다. 줄어든 것은 **우선 검토 대상**이다.
