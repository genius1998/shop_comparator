실패 처리와 한계

  • 서버에 연결하지 못하면 상단에 안내를 띄우고 다음 주기에 다시 시도합니다.

해결하려는 문제와 역할

수집은 수십 분이 걸리고 중간에 쇼핑몰이 거절하거나 연결이 끊깁니다. 무엇이 끝났고 무엇이 남았는지 모르면 처음부터 다시 돌려야 합니다. 작업 관리는 모든 수집·검토를 작업 단위로 실행하고, 대상 하나하나의 처리 상태를 남깁니다.

입력 → 처리 → 출력

입력작업 종류, 대상 상품, 사용하는 쇼핑몰
→
처리같은 쇼핑몰 작업은 하나만, 대상마다 pending → ok / failed / skipped 기록
→
출력진행률, 요약, 실패 원인, 남은 항목 목록

실행 · 취소 · 실패 · 재시도

  1. 시작: 대상 전부를 pending으로 등록
  2. 상품 하나 처리
  3. 성공 → ok / 실패 → failed + 원인
  4. 중단·인증 오류·연속 실패 → 작업 종료, 나머지는 pending
  5. [실패·미처리만 다시 실행]
  6. failed + pending만 새 작업으로

실패 처리와 한계

  • 인증(401)·차단(403)·한도(429)는 재시도하지 않고 즉시 멈춥니다. 연결 끊김은 5초 뒤 한 번만 다시 시도하고 3회 연속이면 멈춥니다.
  • 서버가 꺼져 끝나지 못한 작업은 다음 시작 때 "서버 종료로 중단"으로 정리되고 남은 항목을 다시 실행할 수 있습니다.
  • 자동 재개는 하지 않습니다. 사용자가 버튼을 눌러야 합니다. 유료 VLM 호출은 재실행 때 자동으로 반복하지 않습니다.
  • 재실행 검증은 테스트용 어댑터로만 했습니다. 실제 쇼핑몰 장애 상황에서의 재실행은 확인하지 않았습니다.

  • 수집 중에 도는 자동 판별기도 같은 정책을 따릅니다. 규칙이 확정한 것만 바로 등록하고, 언어 모델의 선택은 제안으로 저장해 검수 화면으로 보냅니다. 예전에 모델이 직접 등록한 매칭은 지우지 않고 "AI 등록(미검수)"로 표시하며 승인 전에는 가격 비교에서 뺍니다. 그중 색상이 다른 상품 1건이 있었습니다.

해결하려는 문제와 역할

규칙으로 확정하지 못한 상품은 사람이 양쪽 이미지를 보고 같은 상품인지 가려야 했습니다. VLM은 그 검토의 후보를 먼저 제안합니다. 제안은 저장만 되고 매칭을 바꾸지 않습니다.

입력 → 처리 → 출력

입력무신사 썸네일 1장, KREAM 후보 썸네일 N장(512px), 상품명·브랜드·모델번호
→
처리JSON 스키마를 지정한 한 번의 호출, 응답 검증
→
출력same / different / uncertain, 고른 후보, 사유, 모델명, 시각, 토큰

내부 흐름

  1. 이미지·후보 확인
  2. 이미지 없음·후보 없음 → 오류로 기록
  3. 같은 후보 목록의 판정이 이미 있으면 건너뜀
  4. 모델 호출 또는 저장된 판정 재생
  5. 응답 검증
  6. 형식 오류·후보 밖 ID·오래된 판정 → 제안으로 쓰지 않음
  7. vlm_suggestions에 저장
  8. 사람 검수 대기

구조화된 응답과 검증

// 모델에 요구하는 응답 형식 (matching/vlm_match.py SCHEMA)
{"decision": "same" | "different" | "uncertain",
 "kream_id": "12831", "confidence": 0.99, "reason": "..."}

# 응답 검증 (services/vlm_review.py validate)
decision not in (same, different, uncertain)      -> InvalidAnswer("format")
decision == same and kream_id not in candidates   -> InvalidAnswer("unknown_candidate")
confidence가 0~1 밖이거나 숫자가 아님              -> 값을 비움 (추정하지 않음)
판정 시각 < 후보 수집 시각                          -> InvalidAnswer("stale")

Qwen3-VL-8B (자체 GPU)gpt-5.4-minigpt-5.4-nano
정확도92.0%87.0%73.0%
다른 상품을 동일로 판정5 / 502 / 500 / 50

실패 처리와 한계

  • 신뢰도는 모델이 스스로 출력한 값입니다. 화면에 "확률 아님"으로 표시하고 자동 승인에 쓰지 않습니다. 실제로 틀린 "동일" 판정의 신뢰도가 0.84~0.98이었습니다.
  • 유료 호출은 최대 호출 수를 입력해야 시작되고 한도에서 멈춥니다. API 실패는 그 상품의 시도만 오류로 남기고 기존 매칭과 이전 판정을 건드리지 않습니다.
  • 실행 중 중단하면 끝난 상품의 판정은 남고 나머지는 미처리로 남습니다.
  • 웹의 실시간 호출 경로는 모의 테스트로만 검증했습니다. 실제 판정 246건은 명령줄 도구로 실행해 저장한 것입니다.
  • 썸네일 한 장으로는 색상만 다른 상품, 같은 브랜드의 닮은 모델을 자주 구분하지 못합니다.

해결하려는 문제와 역할

VLM은 틀립니다. 틀린 매칭은 곧 틀린 가격 비교이므로, 사람이 확인한 매칭만 가격 비교에 쓰이게 했습니다. 검수 화면은 판단에 필요한 것을 한 장에 모으고 결정과 근거를 이력으로 남깁니다.

입력 → 처리 → 출력

입력양쪽 이미지, 상품명·브랜드·모델번호, VLM 판정과 사유, 충돌 안내
→
처리후보 선택 후 승인 / 거절 / 보류
→
출력검수 이력 1행, 승인이면 확정 매칭 갱신, 거절이면 그 매칭 해제
  1. 카드 펼침 (시간 측정 시작)
  2. 이미지·모델번호·사유 확인
  3. 승인 → kream_search_cache에 human_review로 등록
  4. 거절 → 등록된 매칭 해제
  5. 보류 → 기록만
  6. match_reviews에 이력 추가
-- 제안과 결정은 서로 다른 테이블이다

실패 처리와 한계

  • 후보 목록에 없는 상품은 승인할 수 없습니다. 잘못된 요청은 이력을 남기지 않고 거절됩니다.
  • 거절해도 매칭 행과 출처, 수집한 시세는 지우지 않습니다. "검수 거절"로 남고 가격 비교에서만 빠집니다.
  • 아직 사람이 이 화면으로 검수한 기록이 없습니다. 저장소의 기존 라벨(동일 14, 아님 6, 보류 3)은 AI 보조 도구가 만든 것이며 사람 미검수입니다.
  • 검토 시간은 측정 기능만 있습니다. 수동 대비 AI 보조의 시간 감소율은 측정하지 않았으므로 제시하지 않습니다.
  • "AI 제안 숨기기"로 수동 조건을 만들 수 있습니다. 절차는 docs/review-measurement.md에 있습니다.

해결하려는 문제와 역할

KREAM은 사이즈마다 시세가 다릅니다. 상품 단위가 아니라 같은 상품의 같은 사이즈끼리 비교해야 합니다. 비교는 확정된 매칭만 쓰고, 결과를 저장하지 않고 요청할 때마다 양쪽 테이블에서 계산합니다.

입력 → 처리 → 출력

한계

  • 독립된 사람이 검수한 라벨이 없습니다. 라벨은 모델번호 일치(153)와 AI 보조 검토(21)에서 왔습니다.
  • 118 → 167은 확인해 확보한 매칭 수이며 전체 정확도가 아닙니다. 증가 49개 중 35개는 규칙 개선, 14개는 VLM 제안을 검토해 채택한 것입니다.
  • AI 보조 라벨은 VLM이 "동일"이라고 한 것만 검토해 만들었습니다. VLM이 놓친 동일 상품 수는 모릅니다.
  • 표본이 작습니다. 평가용에서 오매칭 3~4건은 1~2건 차이로 순위가 바뀝니다. 어느 방법도 무오류라고 할 수 없습니다.
  • 미실행: 텍스트만 주는 언어 모델(B-LLM), "동일 상품 없음" 사례의 VLM 판정, 로컬 모델의 1:N 판정.
이 항목은 구현되지 않았습니다. 방향과 선행 조건만 적습니다.

목표

사람이 볼 필요가 없는 매칭은 자동으로 확정하고, 사람은 애매한 것만 보게 하는 것입니다. 지금은 규칙으로 확정된 것 외에는 모두 사람이 승인해야 합니다.

자동 승인을 아직 넣지 않은 이유

  • 모델 출력 신뢰도가 맞은 판정과 틀린 판정을 가르지 못했습니다(틀린 "동일"의 신뢰도 0.84~0.98).
  • 정답 라벨이 사람의 검수를 거치지 않았습니다. 자동 승인의 기준을 정할 근거가 부족합니다.

선행 조건

  1. 검수 화면으로 사람 라벨 축적
  2. 사람 라벨로 재평가
  3. 두 모델이 일치하고 모델번호와 충돌하지 않는 경우의 오판율 측정
  4. 기준을 정한 뒤 제한적으로 자동 승인

그 밖의 미구현·미실행

  • 구매·입찰·결제의 자동화: 구현하지 않았습니다. 입찰용 엑셀을 만드는 데까지입니다.
  • 수수료·배송비를 반영한 순이익 계산: 없습니다.
  • 텍스트 전용 언어 모델 비교, "동일 상품 없음" 사례의 VLM 판정: 미실행.
  • 배포, 다중 사용자, 스케줄러: 없습니다.
