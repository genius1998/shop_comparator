# 남은 제한 사항과 개선 과제

2026-10-09 기준.

## 1. 검증하지 못한 것

| 항목 | 상태 | 필요한 것 |
|---|---|---|
| KREAM 계정 자동 입력 로그인, `.env` 버튼 | 무신사 자동 입력 로그인은 사용자가 실행해 성공. KREAM 자동 입력과 `.env` 버튼은 실계정으로 실행하지 않음 | 사용자가 버튼을 눌러 확인 |
| 보강한 KREAM 로그인 완료 감지 | 저장된 프로필의 인증 확인은 성공. 로그인 창을 처음부터 다시 통과시켜 보지는 않음 | KREAM에서 로그아웃 후 다시 로그인 |
| POIZON 로그인·가격 수집 | 기존 모듈 호출로 이식만 함 | POIZON 셀러 계정 |
| 이벤트 자동화(자동·낮·밤 모드), 가격변동 모니터링 | 모의 테스트만 | 장시간 실행 |
| 디스코드 알림 발송 | 모의 테스트만 | 웹훅 URL |
| 브랜드·카테고리 방식 수집 | 목록 표시와 입력 검증만 확인 | 실행 |
| 무신사 로그인 토큰 유효 기간 | 측정하지 않음 | 시간 경과 후 세션 확인 |

## 2. 동작상의 제한

- **자동 매칭 성공률**: KREAM 검색 결과 카드에는 모델번호가 없다. 기존 검증기는 모델번호 근거가 없으면 후보를 채택하지 않으므로 자동 매칭이 "매칭 없음"으로 끝나는 경우가 많다(실측: 3976349). 지금은 매칭 탭에서 직접 지정해야 한다. 개선안: 후보의 KREAM 상품 페이지에서 모델번호를 읽어 검증기에 넘긴다.
- **회원가 조회 속도**: 사이즈 하나에 약 2초(장바구니 → 주문서 → 쿠폰). 상품 100개 × 사이즈 10개면 30분 이상 걸린다. 빠른 모드(옵션 추가금이 같은 사이즈는 대표 1개)는 출처를 표시하지만 정의상 사이즈별 실측이 아니다.
- **바로구매 장바구니 변경**: 회원가 조회는 계정의 "바로구매" 대기 항목을 마지막 조회 옵션으로 바꾼다. 일반 장바구니는 건드리지 않고 주문·결제도 하지 않는다.
- **주문 불가 상품**: 재고가 있어 보여도 주문서 단계에서 "판매 종료"인 상품은 회원가를 구할 수 없다(1527076).
- **KREAM 창**: KREAM은 헤드리스 브라우저를 거절하므로 KREAM 작업 중 최소화된 Chrome 창이 뜬다.
- **작업 시작 지연**: 작업마다 Chrome을 새로 띄워 5~20초가 든다.
- **거래량 필터의 30일 건수**: 최근 체결 100건만 보므로 상한이 100이다(GUI와 동일).
- **사이즈 매칭**: 같은 체계끼리만 매칭한다. 무신사가 mm, KREAM이 US로 표기한 상품은 비교되지 않는다. 브랜드별 공식 사이즈표를 근거로 한 변환은 구현하지 않았다.
- **알림 규칙**: 수익 알림은 기존 GUI 규칙(무신사 회원가 − KREAM 즉시구매가 ≥ 알림 마진)을 그대로 옮겼다. 무신사에서 사서 KREAM에 파는 차익(KREAM 즉시판매가 − 무신사 회원가)은 화면과 엑셀의 "판매 차익" 열로만 제공한다.
- **모니터링·자동화 재시작**: 서버를 다시 켜면 대상 목록은 복구되지만 루프는 자동으로 다시 시작하지 않는다.
- **단일 사용자, 로컬 전용**: 127.0.0.1에서만 접속한다. Flask 개발 서버를 쓴다.

## 3. 쇼핑몰 변경에 취약한 지점

| 지점 | 바뀌면 나타나는 증상 |
|---|---|
| 무신사·KREAM 로그인 화면의 입력란 | "로그인 입력란을 찾지 못했습니다" → 수동 로그인으로 우회 |
| KREAM 페이지 내장 설정(`apiVersion` 등)의 위치 | KREAM API 403(`blocked`) |
| KREAM 시세 응답의 액션 이름(`instant_buy` 등)·버튼 문구 | 즉시구매가가 비거나 "사이즈를 찾지 못했습니다"(`schema`) |
| 무신사 주문서 응답 필드 | 회원가 확인 실패(`schema`, `pricing`) |
| 쇼핑몰의 자동화 브라우저 정책 | 403 또는 500. 프로그램은 우회하지 않는다 |

## 4. 코드 정리 과제

- 데스크톱 GUI(`shop_comparator/desktop/gui.py`)는 위치만 옮기고 내용은 손대지 않았다. 중복 메서드, 깨진 한글 문자열, 호출되지 않는 프록시 창 코드가 그대로 있다. GUI의 엑셀 생성에는 입찰가 반올림 오차(T7)가 남아 있다.
- `desktop/` 아래 모듈과 `shops/get_kream_price6.py`, `shops/kream_login.py`, `shops/proxy_manager.py`는 GUI 시절 코드다. 지금 KREAM 정책(헤드리스·비브라우저 거절, 버전 헤더)에서는 GUI의 KREAM 기능이 동작하지 않을 가능성이 높다. 확인하지 않았다. 웹 경로는 프록시 목록을 쓰지 않는다.
- DB 연결을 닫지 않고 가비지 컬렉션에 맡기는 기존 방식을 유지했다.
- 런타임 데이터(DB, 쿠키, 로그, `match_review/`)는 실행 폴더 기준 경로다. 프로젝트 루트에서 실행해야 한다.
- 변환된 import 문은 정렬하지 않았다.
